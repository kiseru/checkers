## Context

Страница входа `/login` содержит форму с одним полем — "Имя пользователя". Вход выполняется через `POST /login` (см. `LoginController.login`), после чего пользователь перенаправляется на страницу комнат. Бэкенд хранит авторизацию в сессии (`uid`). Хранение последнего введённого логина в браузере не реализовано: пользователь обязан вводить логин каждый раз.

Изменение не затрагивает серверную часть — это чисто фронтенд-функциональность на странице `login.html`.

## Goals / Non-Goals

**Goals:**
- Сохранять последний успешно введённый логин в браузере пользователя
- Автоматически подставлять сохранённый логин в поле ввода при загрузке страницы `/login`
- Минимальная, ненавязчивая реализация без изменения UX остальных страниц

**Non-Goals:**
- Хранение пароля или других данных (пароля в приложении нет)
- Мультиаккаунтная поддержка (список нескольких логинов)
- Сохранение логина на сервере или в cookie
- Изменение бэкенд-логики авторизации и сессий

## Decisions

### Хранение логина в `localStorage`
Для сохранения логина используется Web Storage API — `localStorage`. Это позволяет хранить значение в браузере без истечения срока и без передачи на сервер.

- **Альтернатива (отклонена): cookie** — cookie отправляется на сервер при каждом запросе, что излишне для чисто клиентских данных и не требуется серверу. `localStorage` проще и не увеличивает сетевой трафик.
- **Альтернатива (отклонена): `sessionStorage`** — очищается при закрытии вкладки/браузера, не обеспечивает постоянное сохранение логина между сессиями.

### Ключ хранилища
Используется константный ключ `lastLogin`. Ведение отдельного общего JS-модуля не требуется — логика сохраняется локально на странице входа.

### Точка сохранения
Сохранение выполняется в обработчике отправки формы (событие `submit`) до фактической отправки на сервер, из значения поля ввода. Это гарантирует запись именно того логина, который пользователь ввёл и подтвердил нажатием "Войти".

### Восстановление значения
При загрузке страницы (`DOMContentLoaded`) значение из `localStorage` подставляется в поле ввода, если оно там присутствует.

## Risks / Trade-offs

- [Пользователь ввёл логин, но вход не прошёл] → Mitigation: сохранение выполняется по факту ввода в момент submit; так как на странице нет невалидного входа с ошибкой, а BAD_REQUEST (пустой логин) — редкий случай, риск минимален.
- [`localStorage` недоступен (приватный режим / отключён)] → Mitigation: доступ к `localStorage` оборачивается в `try/catch`, при ошибке функциональность просто не работает без падения страницы.
- [Данные видны в DevTools] → Mitigation: это не секретные данные (логин не является чувствительной информацией), поэтому приемлемо.
