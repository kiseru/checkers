## Context

В проекте используется Spring Boot с Thymeleaf для серверного рендеринга HTML-страниц. Комнаты хранятся в памяти (`ConcurrentHashMap` в `RoomRepositoryImpl`). Каждая комната (`Room`) содержит `whitePlayer` и `blackPlayer` — если одно из полей `null`, в комнате есть свободное место.

Текущая навигация: главная страница (`/`) → логин (`/login`) → создание/поиск комнаты (`/room/create`) → игра (`/game`). Нет возможности увидеть список существующих комнат.

## Goals / Non-Goals

**Goals:**
- Страница `/rooms` со списком комнат, где есть свободное место
- Кнопка "Присоединиться" для каждой комнаты в списке
- Кнопка "Создать игру" над списком, ведущая на `/room/create`
- Эндпоинт `GET /rooms` для отображения страницы
- Эндпоинт `POST /rooms/{roomId}/join` для присоединения к комнате
- Метод в `RoomRepository` для поиска комнат со свободными местами

**Non-Goals:**
- Сортировка или фильтрация списка комнат
- Автообновление списка через WebSocket/long-polling (статическая страница)
- Отображение занятых/полных комнат
- Удаление комнат

## Decisions

1. **Новый шаблон `/templates/room/index.html` вместо отдельной папки**
   - Следует существующей структуре: `room/create.html` уже лежит в `templates/room/`
   - Путь `room/index` соответствует Thymeleaf-резолвингу для `GET /rooms`

2. **Новый метод `findRoomsWithAvailableSlot()` в `RoomRepository`**
   - Возвращает список комнат, где `whitePlayer == null || blackPlayer == null`
   - Простая фильтрация in-memory, так как хранилище — `ConcurrentHashMap`

3. **Присоединение через `POST /rooms/{roomId}/join`**
   - Отдельный эндпоинт, а не переиспользование `POST /room/create`
   - `POST /room/create` ожидает `roomId` и `color` как параметры формы и сразу редиректит в игру
   - Новый эндпоинт будет определять свободный цвет автоматически и редиректить в игру

4. **Автоматическое определение цвета при присоединении**
   - Если свободно место белых — игрок получает белый цвет
   - Если свободно место чёрных — игрок получает чёрный цвет
   - Если оба места заняты — ошибка (но такой комнаты не будет в списке)

5. **Страница списка доступна только авторизованным пользователям**
   - Проверка `@SessionAttribute uid` как в существующих контроллерах
   - Редирект на `/login` если не авторизован

## Risks / Trade-offs

- **Риск: гонка при присоединении** — два игрока могут одновременно нажать "Присоединиться" к одной комнате. **Митигация:** синхронизация через `synchronized(room)` в `RoomServiceImpl.addPlayer()`, как уже реализовано для других операций.
- **Риск: список комнат не обновляется автоматически** — пользователь может видеть комнаты, которые уже заполнились. **Митигация:** при попытке присоединиться к заполненной комнате возвращать ошибку с предложением обновить список. Это приемлемо для MVP.
- **Риск: производительность при большом количестве комнат** — фильтрация по всем комнатам в памяти. **Митигация:** для текущего масштаба (in-memory хранилище) это не проблема. В будущем можно добавить индексацию.
