## Why

Сейчас комната идентифицируется целочисленным ID, который пользователь вводит вручную при создании. Это неудобно: пользователю нужно придумывать и вводить ID, а также возможны коллизии. Нужно заменить ручной ввод ID на автоматическую генерацию UUID, а также дать пользователю возможность задавать произвольное человекочитаемое название комнаты.

## What Changes

- **BREAKING**: Тип идентификатора комнаты (`Room.id`) меняется с `Int` на `UUID`
- **BREAKING**: ID комнаты больше не вводится пользователем, а генерируется автоматически при создании комнаты
- На странице создания комнаты поле `ID комнаты` заменяется на поле `Название комнаты` (произвольный текст)
- В модели `Room` добавляется поле `name: String` — название комнаты, задаваемое пользователем
- Логика поиска/создания комнаты меняется: теперь комната всегда создаётся новая (с UUID), а не ищется по ID
- Список комнат на странице `/room` отображает название вместо ID
- Все места, где используется `roomId: Int`, меняются на `roomId: UUID`

- `room-name`: Возможность задавать произвольное название комнаты при создании. Название отображается в списке комнат.

## Impact

- **Model**: `Room.id` меняется с `Int` на `UUID`, добавляется поле `name: String`
- **Repository**: `RoomRepository` — сигнатуры методов меняются с `Int` на `UUID`, хранилище меняет ключ с `Int` на `UUID`
- **Service**: `RoomService.findOrCreateRoomById(roomId: Int)` → `RoomService.createRoom(name: String): Room`. Логика упрощается: всегда создаётся новая комната.
- **Controller**: `RoomController` — параметры `roomId` меняются с `Int` на `UUID`. POST `/room/create` принимает `name` вместо `roomId`. Пути вида `/{roomId}/...` используют UUID.
- **Templates**: `create.html` — поле ID заменяется на поле названия. `index.html` — отображение названия комнаты.
- **Tests**: `RoomServiceImplTest` — тесты используют `Room(UUID, Board)` вместо `Room(Int, Board)`. Тесты `findOrCreateRoomById` переделываются под новую логику создания.
