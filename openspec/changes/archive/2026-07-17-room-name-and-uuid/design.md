## Context

Сейчас комната (`Room`) имеет целочисленный `id: Int`, который пользователь вводит вручную на странице создания комнаты. Репозиторий (`RoomRepositoryImpl`) хранит комнаты в `ConcurrentHashMap<Int, Room>`. Сервис (`RoomServiceImpl.findOrCreateRoomById`) ищет комнату по ID или создаёт новую, если не найдена.

Необходимо:
1. Изменить тип ID с `Int` на `UUID` с автоматической генерацией
2. Добавить поле `name: String` — название комнаты, которое задаёт пользователь
3. Убрать поле ввода ID со страницы создания, добавить поле ввода названия
4. Упростить логику: теперь POST `/room/create` всегда создаёт новую комнату (вместо findOrCreate)

## Goals / Non-Goals

**Goals:**
- Замена `Room.id` с `Int` на `UUID`
- Добавление поля `Room.name`
- Изменение страницы создания комнаты: поле ID → поле названия
- Отображение названия комнаты в списке комнат
- Автоматическая генерация UUID при создании комнаты

**Non-Goals:**
- Не меняется логика игры, доски, ходов
- Не меняется модель `User`
- Не добавляется редактирование названия комнаты после создания

## Decisions

### 1. Тип UUID — `java.util.UUID`
**Решение**: Использовать `java.util.UUID` (уже используется в проекте для `User.id` и `Board.id`).
**Альтернатива**: `String` — но UUID даёт типобезопасность и уже является стандартом в проекте.
**Rationale**: Консистентность с существующим кодом.

### 2. Генерация UUID — `UUID.randomUUID()`
**Решение**: Генерировать UUID на стороне сервера при создании комнаты.
**Rationale**: Уже используется для `Board` и `User`. Простая и надёжная генерация.

### 3. Хранилище — `ConcurrentHashMap<UUID, Room>`
**Решение**: Меняется тип ключа в `RoomRepositoryImpl` с `Int` на `UUID`.
**Rationale**: Минимальное изменение, сохраняется потокобезопасность.

### 4. Логика создания комнаты — всегда новая
**Решение**: Вместо `findOrCreateRoomById(roomId: Int)` — `createRoom(name: String): Room`. Всегда создаётся новая комната.
**Rationale**: UUID уникален, нет необходимости искать существующую комнату. Упрощает логику.

### 5. URL-пути с UUID
**Решение**: Пути вида `/{roomId}/join` и `/{roomId}/board` принимают UUID в строковом представлении. Spring автоматически конвертирует `java.util.UUID` из path-переменной.
**Rationale**: Spring Boot поддерживает конвертацию UUID из строки в path-переменных.

### 6. Сессия — `session.setAttribute("roomId", uuid)`
**Решение**: В сессии `roomId` хранится как `UUID` (объект), а не как `Int`.
**Rationale**: Минимальное изменение, UUID сериализуется корректно.

## Risks / Trade-offs

- **[Risk]** UUID в URL менее удобен для пользователя (нельзя вручную ввести `http://.../room/123/join`).
  → **Mitigation**: Пользователь теперь не вводит ID вручную, а переходит по ссылке из списка комнат или создаёт новую.
- **[Risk]** Существующие сессии со старым `roomId: Int` перестанут работать.
  → **Mitigation**: Это BREAKING change, но проект на стадии beta, и база данных не используется (in-memory storage).
- **[Risk]** Конвертация UUID в шаблонах Thymeleaf может потребовать явного вызова `toString()`.
  → **Mitigation**: Thymeleaf автоматически вызывает `toString()` для объектов, но в URL-путях нужно убедиться, что UUID передаётся как строка.
